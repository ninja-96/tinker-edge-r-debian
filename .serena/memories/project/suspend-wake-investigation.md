Suspend (S3) wake — state as of 2026-11-05 (feature NOT working, frozen at 0.5.0; 0.5.1 cancelled by the user).
Symptom: `echo mem` / `systemctl suspend` enters a clean deep sleep (AP power off); the board does not wake from the RTC alarm (rk808 wakealarm) nor the power key; only a physical reset brings it back. A wake from a successful deep sleep is a cold boot from the boot ROM (uptime resets; the NPU die comes back in its boot ROM 2207:180a with flapping USB enumeration).
VERIFIED (ruled out): the alarm reaches the SoC while running (rk808 alarm -> INT-ALL -> GPIO1_C2 = IRQ 49 -> regmap domain -> IRQ 55, counters grow); the kernel wake-arming chain is intact in 6.18.60 (rk808_rtc_suspend -> enable_irq_wake(55) -> regmap_irq_set_wake -> bus sync via regmap_irq_sync_unlock/.irq_bus_sync_unlock (kernel/irq/internals.h) -> enable_irq_wake(49) -> irq_gc_set_wake; rockchip_irq_suspend writes int_mask = ~wake_active; called from the IRQ core PM hook, kernel/irq/generic-chip.c irq_gc_suspend); the DTS pin matches the vendor DTS and the vendor pinctrl marks all bank pins wake-able; the wake-related kernel files are identical in 6.18.56/59/60 (the regression is not in the kernel; per the old README the RTC wake worked on 2026-10-28).
BL31 (closed blob blobs/rockchip/rk3399pro_bl31_v1.35.elf, the default in scripts/build-uboot.sh; USE_TFA=1 builds the open TF-A v2.15.0 which has no wake configuration): SIP V2 (version FID 0x8200000a -> a1=2); service 0x82000003 is live: call type 0x01 SUSPEND_MODE_CONFIG and 0x02 WKUP_SOURCE_CONFIG are accepted (ret 0), unknown call type -> 0xffffffff (NOT 0xffff0001 as in the V1 header); remotectl 0x8200000b present (GET_WAKEUP_STATE 0xf3 -> 0xf0000020); LAST_LOG 0x8200000e -> -2. ELF strings: "wakeup source config[0x%x]", "exceed support suspend gpio number", "remotectl set PWRKEY 0x%x".
Vendor mechanism (reference/src/debian-kernel 4.4 and reference/src/rk-kernel-6.12): drivers/soc/rockchip/rockchip_pm_config.c reads the DTS node rockchip-suspend (rockchip,wakeup-config / sleep-mode-config) and sends the SIP SMCs; that node is status="disabled" in the rk3399 dtsi in BOTH trees (4.4 ~line 3020, 6.12 ~line 3303), so vendor systems run on the BL31 built-in defaults. Vendor DTS values: wakeup 0x4 (RKPM_GPIO_WKUP_EN), sleep-mode 0x7e (ARMPD|PERILPPD|DDR_RET|PLLPD|OSC_DIS|CENTER_PD|AP_PWROFF). The 6.12 driver additionally sends a LINUX_PM_STATE call type (value unknown, the 6.12 tree is partial and has no headers) and re-sends the configs in the suspend-prepare phase.
Setting the vendor mask+mode at boot AND in PM_SUSPEND_PREPARE (notifier) did not bring the wake back (several S3 tests, alarm +90 s).
NPU variable: tinker_npu_power_suspend() disables rk808-clkout2 (the 32 kHz to the SoC) at suspend. With the NPU die on and the driver bound -> clean deep sleep; with the driver unbound (die stays on, npu-daemon running) -> the suspend ABORTS after ~20 s (freezer) and the board then crashes/reboots (no journal of the aborted boot).
