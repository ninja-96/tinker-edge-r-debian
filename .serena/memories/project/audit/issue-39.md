# 39. GoogLeNet INT8 не проходит strict NPU из-за PADV2 с квантованным нулём

2026-11-27, RK3399Pro, LiteRT 2.4.0. litert-community/googlenet, файл googlenet_int8_channelwise.tflite SHA256 c5fede5107c7b9d3ab379b5c05d7754a1a1d0b86e075a68f03d824838ff9fec6. До исправления CPU исполняет модель, device=npu отказывает с PADV2. Все 12 узлов используют константу −128 при zero_point −128. В rewrite_ops.h преобразуем PADV2 в PAD только для константного заполнения с кодом нуля, одинаковой per-tensor квантизацией INT8/UINT8 и рангом входа до четырёх. Приёмка: оба типа на отдельном операторе, исходная модель целиком на NPU, контроль ненулевого заполнения и динамического входа. Численные расхождения полных моделей отслеживаются в issue-38.

Закрыта 2026-11-27. После замены 12 PADV2 все 195 узлов преобразованного GoogLeNet прошли на NPU. Прогретая медиана 19.28 мс против 475.22 мс на CPU, top-1 совпал 9/9, наибольшее расхождение 7 кодов. Отдельные INT8 и UINT8 PADV2 совпали с CPU; при ненулевом и динамическом заполнении strict NPU отказал в обоих типах. Штатный selftest 24/24.
