# 7. Free-сборка может выбрать загрузчик с закрытым BL31

**Где и почему.** `scripts/make-free-image.sh` передаёт `UBOOT_BIN` с абсолютным путём хоста, тогда как `run.sh` монтирует репозиторий в `/work`. Из-за резервного выбора в `scripts/build-image-mainline-uboot.sh` это часто остаётся незаметным. Отдельно `run.sh` наследует `BL31`, который имеет приоритет над `USE_TFA=1` в `scripts/build-uboot.sh`. Так закрытый BL31 может попасть в файл с обычным именем `u-boot-rockchip.bin`. Сравнение с этим же файлом не установит происхождение BL31.

**Что изменить.** В штатной free-сборке явно выбрать собранный открытый `out/bl31-tfa.elf` и соответствующий `out/u-boot-rockchip.bin` по путям внутри рабочего каталога контейнера. Исключить влияние внешней подмены BL31 на этот режим. При отсутствии обязательного артефакта free-сборка должна завершиться ошибкой до упаковки. Сохранить поддержку явного BL31 для обычной сборки.

**Приёмка.** Проверить передачу аргументов через `run.sh` при расположении репозитория вне `/work` и заданном снаружи альтернативном `BL31`. В журнале free-сборки выбран открытый ELF, отсутствие этого ELF завершает сборку ошибкой. Для готового образа выполнить исправленную проверку из задачи 5. Сравнение байтов загрузчика и проверка выбора ELF нужны обе.

**Статус:** Исправлено локально, ожидает платы. 2026-11-24, коммит eb0c824. make-free-image.sh экспортирует контейнерно-относительные BL31=out/bl31-tfa.elf и UBOOT_BIN=out/u-boot-rockchip.bin (перекрывают внешнее окружение — свободная сборка не берёт закрытый EL2) и проверяет оба артефакта до упаковки. Механизм проверен: внешний BL31 приоритетен над USE_TFA=1 (build-uboot.sh:15-18), экспорт имеет приоритет над внешним; относительные пути резолвятся в /work. Реальная free-сборка и загрузка на плате — ожидает.
