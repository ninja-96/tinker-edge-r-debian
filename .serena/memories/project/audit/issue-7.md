# 7. Free-сборка может выбрать загрузчик с закрытым BL31

**Где и почему.** `scripts/make-free-image.sh` передаёт `UBOOT_BIN` с абсолютным путём хоста, тогда как `run.sh` монтирует репозиторий в `/work`. Из-за резервного выбора в `scripts/build-image-mainline-uboot.sh` это часто остаётся незаметным. Отдельно `run.sh` наследует `BL31`, который имеет приоритет над `USE_TFA=1` в `scripts/build-uboot.sh`. Так закрытый BL31 может попасть в файл с обычным именем `u-boot-rockchip.bin`. Сравнение с этим же файлом не установит происхождение BL31.

**Что изменить.** В штатной free-сборке явно выбрать собранный открытый `out/bl31-tfa.elf` и соответствующий `out/u-boot-rockchip.bin` по путям внутри рабочего каталога контейнера. Исключить влияние внешней подмены BL31 на этот режим. При отсутствии обязательного артефакта free-сборка должна завершиться ошибкой до упаковки. Сохранить поддержку явного BL31 для обычной сборки.

**Приёмка.** Проверить передачу аргументов через `run.sh` при расположении репозитория вне `/work` и заданном снаружи альтернативном `BL31`. В журнале free-сборки выбран открытый ELF, отсутствие этого ELF завершает сборку ошибкой. Для готового образа выполнить исправленную проверку из задачи 5. Сравнение байтов загрузчика и проверка выбора ELF нужны обе.

**Запись истории:** Исправлено локально, ожидает платы. 2026-11-24, коммит eb0c824. make-free-image.sh экспортирует контейнерно-относительные BL31=out/bl31-tfa.elf и UBOOT_BIN=out/u-boot-rockchip.bin (перекрывают внешнее окружение — свободная сборка не берёт закрытый EL2) и проверяет оба артефакта до упаковки. Механизм проверен: внешний BL31 приоритетен над USE_TFA=1 (build-uboot.sh:15-18), экспорт имеет приоритет над внешним; относительные пути резолвятся в /work. Реальная free-сборка и загрузка на плате — ожидает.

**Повторная проверка 2026-11-24, ac2e53b. Открыта повторно.** Путь out/bl31-tfa.elf доступен из /work, но binman работает в build/u-boot-obj. По каталогам поиска фактической команды binman относительный файл не найден; абсолютный найден. Нормализовать BL31 внутри контейнера до make -C. Проверить реальную упаковку с чистым каталогом и выбранный ELF.

## Порядок исправления и проверка результата

Проверять две рабочие директории. make-free-image.sh выбирает открытый ELF относительно /work, но build-uboot.sh запускает make -C с отдельным O=build/u-boot-obj. В локальной проверке get_input_filename из поставляемого U-Boot вернул None для относительного пути и нашёл тот же ELF по абсолютному пути. Нормализовать существующий BL31 внутри контейнера перед передачей make, сохранив обычный режим с явно заданным ELF.

Приёмка. Начать с отдельного чистого каталога объектов, чтобы прежний FIT не скрыл ошибку. Запустить штатный free-путь с внешним альтернативным BL31. В фактической команде binman параметр atf-bl31-path должен указывать на собранный открытый ELF внутри контейнера; упаковка должна завершиться успешно. Отсутствие выбранного ELF должно дать ошибку до упаковки. Предыдущая проверка подтверждает поиск файла, полная сборка остаётся отдельной проверкой.

**Запись истории:** На проверке. 2026-11-24, коммит 926b18c. Относительный `BL31` разрешается в `$PWD/$BL31` после проверки существования (одно место, перед make): binman ищет файл от каталога сборки (O=), где имён относительно корня репозитория нет; явно заданный абсолютный путь не меняется. Полная free-сборка с альтернативным BL31 в чистом объектном каталоге остаётся проверкой на сборке/плате.
