# 3. Выбор device tree изменяет резервную запись extlinux

**Где и почему.** В `overlay/usr/local/sbin/tinker-boot-select` одна подстановка меняет все строки `fdt`. На конфигурации с двумя метками подтверждено, что `previous` теряет путь в `/boot/dtbs.old/`. При откате старое ядро получает дерево устройств нового ядра. Вывод текущего варианта также берёт первую строку `fdt` независимо от метки.

**Что изменить.** Читать и менять `fdt` только внутри блока `label tinker` до следующего `label` или конца файла. Проверить, что целевая запись однозначна. Сформировать результат во временном файле рядом с конфигурацией, сохранить права и резервную копию и только после проверки заменить оригинал. Ветка с Android boot.img использует другой формат.

**Приёмка.** На копиях конфигурации проверить одну метку, обе очередности `tinker` и `previous`, а также отсутствие целевой метки. При успехе меняется только путь в активной записи, вывод без аргументов показывает её вариант, резервный блок побайтно совпадает с исходным. При ошибке исходный файл цел.

**Запись истории:** Исправлено локально, ожидает платы. 2026-11-24, коммит e7a2555. Label-scoped awk меняет `fdt` только внутри блока `label tinker` (ровно одно изменение, иначе отказ), результат во временном файле в том же каталоге, бэкап и права сохранены, `mv` после проверки; вывод показывает вариант блока tinker. Локальная приёмка на синтетических конфигах: 6/6 (одна метка, обе очередности, отсутствие метки, побайтное совпадение резервного блока, исходный файл цел при ошибке). Реальная загрузка на плате — ожидает.
