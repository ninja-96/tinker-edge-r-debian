# 8. Кеш rootfs игнорирует политику смены пароля

**Где и почему.** В `scripts/build-rootfs.sh` ключ кеша включает хеш скрипта и `FREE`, хотя содержимое зависит также от `FORCE_PW_CHANGE`, имени хоста и учётной записи. После тестовой сборки с `FORCE_PW_CHANGE=0` обычная сборка может взять тот же архив и сохранить тестовую политику первого входа. Подсказка предлагает `FORCE=1`, но `run.sh` эту переменную в контейнер не передаёт.

**Что изменить.** Включить в ключ эффективные несекретные параметры rootfs. Для нестандартного пароля обходить кеш без записи пароля или его производных в файл и без публикации отметки, подходящей сборке с паролем по умолчанию. Инвалидировать старую отметку перед пересборкой, публиковать новую только после успешного получения архива. Передавать `FORCE` через `run.sh`.

**Приёмка.** Последовательно собрать с политикой `0 → 1 → 1`. Второй запуск пересобирает архив, третий использует кеш. По полю дня последней смены пароля в архивном `/etc/shadow` проверить требование смены при первом входе, не печатая хеш пароля. Проверить также нестандартный пароль с возвратом к обычному, отказ сборщика и принудительную пересборку через `FORCE=1 ./run.sh scripts/build-rootfs.sh`.

**Запись истории:** Исправлено локально, ожидает платы. 2026-11-24, коммит eb0c824. Ключ STAMP += HOSTNAME_, USER_, PWC (FORCE_PW_CHANGE); нестандартный пароль — не читает кеш и не публикует метку (в архиве лежит этот пароль); старая метка снимается до пересборки, новая публикуется только после успеха; FORCE передаётся run.sh. Логика проверена реальным скриптом со stub'ом mmdebstrap: 8/8 (0→1→1, «отравленный» архив не подставляется, FORCE=1, смена host/user, отказ сборки без метки). Реальная сборка в контейнере — ожидает.

**Сверка всех карточек, 2026-11-24, f86b309.** Штатный build-rootfs.sh со счётчиком вместо mmdebstrap: политика 0 → 1 → 1 дала две сборки. Осталась проверка дня смены пароля в /etc/shadow реально собранного архива; для этого достаточно сборочного окружения.

**Целевая приёмка f86b309, 2026-11-24.** В изолированной копии f86b309 штатным run.sh и mmdebstrap собраны два настоящих ARM64 архива Debian. При FORCE_PW_CHANGE=0 поле 3 пользователя debian из архивного /etc/shadow равно 20781. После изменения на 1 сборка выполнена заново, поле равно 0. При повторной 1 скрипт сообщил up to date; inode, время изменения и размер архива сохранились. Хеш пароля не выводился. Дополнительно через run.sh со счётчиком вместо mmdebstrap проверены обход кеша при нестандартном пароле, новая сборка при возврате к обычному паролю и отсутствие stamp после принудительной сборки с отказом. Комментарий к передаче FORCE_PW_CHANGE внесён в run.sh.
