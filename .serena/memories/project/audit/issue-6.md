# 6. Синхронный вызов NPU из callback ждёт собственный поток

**Где и почему.** В `npu-open/host/rk3399pro_npu.cc` метод `Link::read_loop` исполняет пользовательский callback в потоке чтения. Например, `models()` из callback на том же соединении входит в `Link::call` и ждёт ответа, обработать который может только занятый поток. До тайм-аута задерживаются и другие ответы этого соединения.

**Что изменить.** В общем пути синхронного запроса распознать поток чтения этого соединения и немедленно вернуть понятную ошибку до регистрации запроса и отправки команды. Проверить вызывающие методы, в частности `stop`, который сейчас сбрасывает ссылку до вызова. Отказ не должен частично менять состояние модели. Описать ограничение в публичной документации C++ и Python и показать, что дальнейшую синхронную работу можно передать вызывающему потоку.

**Приёмка.** В callback вызвать `models()` на том же соединении. Ошибка приходит сразу, сервер не получает вложенной команды, следующий обычный запрос завершается. Проверить путь через Python и отсутствие частичного закрытия при отклонённом `stop`. Согласовать с проверкой времени жизни в задаче 2.

**Запись истории:** Исправлено локально, ожидает платы. 2026-11-24, коммит 273c897. `submit()`/`call()` отказывают в запросе с потока-читателя (Error сразу, команда серверу не отправляется). Приёмка с фейковым демоном: callback с `exec` получает ошибку немедленно, следующие синхронные запуски работают, `stop` — UNLOAD сначала, close только после успеха. Python-путь (NpuError) — на плате. Документация обновлена (hpp, docstring).

**Повторная проверка 2026-11-24, ac2e53b. Открыта повторно.** В async_exec ожидание slots->acquire предшествует проверке reader в submit. Callback A на общем Link ждёт слот модели B, когда все её слоты заняты, и блокирует разбор ответов B. Перенести проверку перед ожиданием. reader_tid_ также записывается в новом потоке без синхронизации с первым call; установить идентичность безопасно при публикации или использовать thread_local. Уточнить контракт close, который не посылает запрос. Приёмка с двумя моделями и занятыми слотами.
