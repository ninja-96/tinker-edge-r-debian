# 30. Удалённый тест платы сообщает PASS при ошибке SSH

В scripts/test-board.sh:47 после конвейера printf | ssh | tee берётся PIPESTATUS[0], то есть код printf. Проверено запуском штатного скрипта во временном дереве с заглушкой SSH. При коде удалённой команды 7 скрипт напечатал Board test: PASS и вернул 0.

Исправление: сразу после конвейера сохранить статус SSH и учесть ошибку записи журнала. Приёмка: удалённые коды 0 и 7 приводят к PASS/0 и FAIL/7 соответственно; сбой tee не должен давать успешную проверку. Результаты старых запусков с одной строкой PASS требуют проверки журнала.

**Сверка всех карточек, 2026-11-24, f86b309.** После конвейера printf | ssh | tee скрипт всё ещё берёт PIPESTATUS[0]. На этой же ревизии уже получены PASS и код 0 при коде 7 у SSH. Повторно проверена привязка индекса к printf.

**Итоговая приёмка, 2026-11-24.** После конвейера printf | ssh | tee rc — статус ssh (PIPESTATUS[1]; PIPESTATUS[0] — это printf, всегда 0); сбой записи лога (код tee) теперь считается провалом прогона. Приёмка с заглушкой SSH: удалённый код 0 → PASS/0, код 7 → FAIL/7. Результаты старых запусков с одной строкой PASS требуют проверки журнала (по формулировке исходной задачи).
