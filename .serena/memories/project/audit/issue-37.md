# 37. QUANTIZE с отношением масштабов 1/2 расходится с CPU на полуцелых значениях

Штатная LiteRT 2.4.0 на RK3399Pro: повторная квантизация без смены типа (INT8→INT8, UINT8→UINT8) дала 524 отличающихся элемента из 2048 в каждом случае, максимум один код. CPU округляет половины вверх, VX округляет к чётному. При отношении 1/2 возможны только целые и полуцелые значения до прибавления нулевой точки. Переписывание в один ADD добавляет 1/8 выходного шага, чтобы округлить полуцелые вверх. Остальные отношения и смешанные типы используют прежний путь. Приёмка: все 256 кодов, крайние входные и выходные zero point, насыщение, оба типа, строгое размещение. Результат относится к этому оператору; ошибки свёрток и других операторов отслеживаются отдельно.

Закрыта 2026-11-27. Финальная тестовая прошивка SHA256 0324fb4e09cd0601cf41b0306a64aa613f11a61de508c79f1fd00caee91299af и собранный модуль Python на физической плате: сравнения прошли, штатный npu-selftest 24/24.
