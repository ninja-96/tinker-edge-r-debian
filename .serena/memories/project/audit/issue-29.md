# 29. Аудит free-образа пропускает дополнительные источники APT

Открыта 2026-11-24, ac2e53b. На синтетическом ext4 с main в sources.list и включённым contrib/non-free в sources.list.d/extra.sources штатный scripts/audit-free.sh вернул 0 и RESULT: free. Проверять активные записи как в *.list, так и в *.sources, включая поле Enabled. Приёмка на образах с включённым и отключённым дополнительным источником.

## Порядок исправления и проверка результата

Минимальный образ для проверки: читаемый ext4 по ROOT_START, корректные загрузочные байты и dpkg/status, основной /etc/apt/sources.list с main. Добавить /etc/apt/sources.list.d/extra.sources с полями Types: deb, URIs, Suites и Components: main contrib non-free. Для такого образа scripts/audit-free.sh вернул код 0 и RESULT: free.

При обходе rootfs обработать основной файл, активные строки файлов *.list и отдельные абзацы deb822 в *.sources. Искать компоненты contrib, non-free и non-free-firmware среди значений Components, учитывая переносы. Игнорировать комментарии и абзацы с Enabled: no. Отсутствующий необязательный каталог допустим; ошибку чтения существующего файла учитывать как неполную проверку.

Приёмка. Активный дополнительный источник с запрещённым компонентом в каждом из двух форматов даёт код 1. Образ только с main, закомментированной строкой и отключённым абзацем даёт 0. Ошибка чтения даёт 2. Для каждого случая проверить и код, и итоговое сообщение.

**Запись истории:** На проверке. 2026-11-24, коммит c0d2a0e. Добавлены парсеры активных записей: однострочный формат (группа опций `[...]`, комментарии, компоненты начиная с 4-го токена) для /etc/apt/sources.list и *.list и deb822 для *.sources (абзац до пустой строки, `#` — комментарий, переносы значения `Components`, `Enabled: no` игнорируется, порядок полей в абзаце свободен); /etc/apt/sources.list.d обходится по файлам, отсутствие каталога допустимо; `cat_root` различает «отсутствует» (чисто) и ошибку чтения (файл отвечает на stat, но не на cat — exit 2, непроверенный образ не «free»). Приёмка на синтетических образах: активный extra.sources с non-free → 1, перенос строки с non-free → 1, *.list с группой опций и contrib → 1, main + закомментированная строка + абзац Enabled: no → 0, файл с повреждённым блоком данных (stat отвечает, cat — short read) → 2 без строки RESULT.

**Проверка f86b309, 2026-11-24.** На ext4 с корректной основной конфигурацией активное поле components: non-free в extra.sources дало 0 и RESULT: free. Системный apt-get --print-uris update увидел /non-free/ на тех же файлах, сеть для теста не использовалась. С Components: non-free аудит вернул 1. Строка deb с main и хвостовым комментарием # non-free также дала 1 вместо 0. Учитывать регистр имён полей согласно поведению APT и комментарии в однострочном формате; добавить обе фикстуры к приёмке.

**Сверка всех карточек, 2026-11-24, f86b309.** Парсер deb822 всё ещё сравнивает имя поля с Components с учётом регистра, а однострочный парсер сохраняет хвостовой комментарий. Применимы оба предыдущих наблюдения на f86b309 с настоящими ext4 и apt-get --print-uris.

**Итоговая приёмка, 2026-11-24.** Имена полей deb822 сравниваются без учёта регистра (APT читает их так же: строичное `components: non-free` теперь распознаётся как Components), в однострочном формате хвостовой комментарий отсекается до разбора компонентов (`main  # non-free` — не запрещённый компонент). Приёмка на синтетических образах: 15/15, включая обе фикстуры сверки f86b309.
