# 18. Мёртвый движок остаётся в списке, «стопнутый» RUN не чистит его

(ERRORS.md #10, аудит 2026-11-23.) NPU_LIST/DESCRIBE не смотрят e->pid; RUN при e->pid<=0 отвечает ошибкой вечно; запись с pid=-1 живёт до ручного stop(id).
**Исправление.** 2e81d29: RUN/OPS с мёртвым движком — lk.unlock() затем engine_remove (deadlock исключён: stopper сначала стирает запись из g_engines, потом берёт e->mu; lost-race — безопасный no-op).
**Запись истории:** Закрыта (локально), 2026-11-24. Проверка: компиляция, порядок блокировок по исходникам.

**Сверка всех карточек, 2026-11-24, f86b309.** В хостовом стенде из исходного handle зарегистрирована модель со статусом pid=-1 и сохранённым описанием. До нового RUN ответ LIST содержал модель, DESCRIBE вернул успешный ответ. RUN затем удалил запись. Требуется исключить выдачу остановленной модели при перечислении и присоединении. Проверить LIST и DESCRIBE сразу после остановки, до RUN; отдельно проверить удаление без взаимной блокировки.

**Итоговая приёмка, 2026-11-24.** Engine::pid — std::atomic<pid_t> (движок мёртв, пока pid≤0); LIST и DESCRIBE читают его без e->mu, потому что не должны ждать выполняющегося RUN. Поведенческий стенд с фейковым движком (настоящий handle): зарегистрированная модель с pid=-1 — LIST её не содержит; DESCRIBE ответил ошибкой «the model was stopped» и удалил запись (без ожидания мьютекса модели — взаимной блокировки с параллельным stop нет); второй DESCRIBE — «no such model». Кросс-сборка сервера — rc 0.

**Повторная проверка 2026-11-24. Закрыта.** Положительный PID встречается и у завершившегося дочернего процесса. waitid с WNOWAIT позволяет исключить его из HELLO, LIST, DESCRIBE и повторного LOAD. Счётчик RUN атомарен; размер ответа LIST считается по фактически включённым записям. Локальный процессный тест проверил живой и завершившийся процесс, нулевой счётчик после выхода и возможность последующего waitpid.

Дополнительно выполнен скомпонованный с LiteRT обработчик ARM64 под QEMU. После выхода дочернего процесса до waitpid проверены количество HELLO, два состояния LIST и размер его ответа, ошибка DESCRIBE и удаление из таблицы.
