# 10. build-npu-boot.sh молча подставляет чужой firmware

(ERRORS.md #2, аудит 2026-11-23.) `python3 scripts/npu-fw-tinker.py ... || cp $SRC/boot.img` — при любом ненулевом выходе берётся исходный EVB-образ.
**Проблема.** Нет dtc / прошивка обновлена / текст DTB изменился → EVB-дерево (I2C-регуляторы): «galcore: failed to get regulator», NPU перезагружается при загрузке модели, сборка «успешна».
**Исправление.** 4723a66: npu-fw-tinker.py идемпотентно пропускает уже запатченный (или ASUS) образ (exit 0, байт-в-байт); fallback `|| cp` удалён — set -e останавливает сборку на любом другом падении.
**Запись истории:** Закрыта, 2026-11-24. Проверка: сборка прошивки NPU прошла (out/npu_fw/boot.img, 686 файлов в ramdisk).

**Сверка всех карточек, 2026-11-24, f86b309.** В копии действительной Rockchip boot.img переименована запись RSCE rk-kernel.dtb в rk-otherx.dtb, байты самого дерева сохранены. Запущен штатный build-npu-boot.sh в одноразовом каталоге с существующими host-артефактами прошивки. Код 0, итоговый boot.img опубликован, patch_dts не вызывался для переименованной записи. Требовать ровно одну ожидаемую запись DTB до упаковки. Проверить отказ при её отсутствии и обычную сборку известного образа.

**Итоговая приёмка, 2026-11-24.** npu-fw-tinker.py до упаковки требует ровно одну запись rk-kernel.dtb в RSCE-секции ресурсов boot.img (иначе SystemExit со списком фактических записей), build-npu-boot.sh останавливается по set -e — fallback на чужой образ исключён. Приёмка: настоящая Rockchip boot.img с переименованной записью отклонена (ненулевой код, список записей выведен); штатная сборка известного образа в builder-контейнере (dtc) — rc 0: vdd-npu добавлен, tcs452x/syr837 удалены, размер DTB и образа записан в лог.
