# 38. Полностью делегированный 8-битный граф может расходиться с CPU или работать медленнее

На восьми детерминированных входах tests/npu/dev/compare_quantized.py со штатным CPU LiteRT 2.4.0 на NPU-кристалле. MobileNet V2 UINT8: CPU 115.29 мс, NPU 10.22 мс, максимальная разница 5 кодов. INT8 с группировкой: 112.02 / 30.57 мс, 101 код. Без группировки: 111.94 / 137.31 мс, 18 кодов. На маленькой сети INT8 отключение группировки устраняет расхождение (максимум 2 → 0); на UINT8 остаётся максимум 1. Отдельно LOGISTIC и MUL расходятся до одного кода. Не считать причиной всей ошибки MobileNet только эти два оператора. Для продолжения снять CPU и NPU срезы по первому расходящемуся узлу, отдельно проверить CONV_2D, DEPTHWISE_CONV_2D, bias, requantization, группировку и насыщение с параметрами конкретного слоя. Проверять исходный CPU-граф, холодный strict NPU без кеша, все выходы на идентичных данных, кэш и прогретую задержку. Ложный PASS по косинусу или смешанному плану исключить. Для заявления о качестве задачи нужна отдельная проверка на типичных входах.

2026-11-27. MobileNet V3 large INT8: CPU 99.20 мс, strict NPU 75.95 мс, максимальная разница 22 кода. EfficientNet-B0 INT8: 364.76 / 748.82 мс, 6 кодов. Отдельные слои из net_int8 с настоящими весами и случайными активациями: первый CONV_2D максимум 7 кодов, следующий DEPTHWISE_CONV_2D 18, следующий CONV_2D 46; MEAN и RESHAPE точны на этом наборе. Изолированные свёртки из варианта net_uint8 в диагностических графах отказали при первом запуске; полная модель выполнилась. Не считать отказ изолированной фикстуры доказательством отказа слоя в исходной сети.

Контроль на фотографии rnd/npu/npu_demo/dog_224x224.jpg. Обе версии MobileNet V2 на CPU и strict NPU выбрали класс 156. У UINT8 одинаковое множество top-5 с перестановкой, у INT8 совпали первые три позиции, последние две различаются. Максимальная разница 4 и 3 кода соответственно; одного изображения недостаточно для оценки точности классификации.
