# How a release is made

The order is fixed. Steps 1-2 are done automatically at the start of every major or minor release, x.0.0 or x.y.0 (standing rule of the maintainer, 2026-10-27); a patch release x.y.z (z > 0) keeps the kernel and Debian of its x.y.0; publishing (step 8) only when the maintainer says so.

| # | Step | How |
|---|---|---|
| 1 | **Update the Linux kernel, LiteRT and Debian (Chromium) to the newest versions** | `scripts/check-updates.sh --apply` writes the newest release of the long-term series in `sources.lock` (6.18.x; version and sha256 from kernel.org); `scripts/fetch-sources.sh` downloads it. LiteRT: the newest release tag (standing rule of the maintainer, 2026-11-05 — at every release, including patches: bump `LITERT_*` in `sources.lock`, see mem:project/05-litert-migration-state). Debian: the root file system is built from the live archive, so it is always rebuilt (`./run.sh scripts/build-rootfs.sh`): current point release and security updates, and Chromium (installed from the archive, `scripts/build-rootfs.sh`) — the newest version at build time; `scripts/check-updates.sh` reports when the archive is ahead of `out/rootfs.tar`. A new kernel series (6.19, 7.x) is a separate decision, not part of this step |
| 2 | Check that the new kernel still fits | `patches/linux/*.patch`, `kernel-mods/`, `config/linux-tinker.fragment` must apply and build (`./run.sh scripts/build-kernel.sh`). If a patch no longer applies: stop, rebase it (see [KERNEL.md](KERNEL.md)), tell the maintainer |
| 3 | Check the other pinned sources | `sources.lock` (U-Boot, TF-A, mpp, GStreamer plugins, TIM-VX, the delegate, LiteRT): note new releases in the release notes; they are changed only on purpose |
| 4 | Links and licences | every source, library or tool the project uses has its link and licence (SPDX id and a link to the licence text) in the README section "Upstream and reference repositories", in [NOTICE.md](../NOTICE.md) and, if it ends up in the image, in `/usr/share/doc/tinker-edge-r/licenses/`; new ones are added now, the links are opened to see that they work |
| 5 | Build | From v0.7: `SD=1 scripts/make-image.sh` (or its individual stages), compress `out/tinker-edge-r-debian13-sd.img` with `xz -T0 -9 -k`, generate raw/compressed SHA-256 files and keep `out/packages.txt`. Both full and loader-only eMMC images are local build/recovery options, not published. |
| 6 | Flash and test | Write the SD card (`scripts/flash-sd.sh`), check standalone boot, SD root, expansion, 2 GiB swap and `scripts/test-board.sh` (`RESULT: PASS`). Skipped phases are named in the notes. See [FLASHING.md](FLASHING.md). |
| 7 | Release notes | what is new, what works (with the counts of the test run), known problems, not supported, not tested, install, licences and the written source offer; the SHA-256 of the unpacked image |
| 8 | Publish (only on the maintainer's word) | `git push`, tag `vX.Y.Z`, `gh release create` with only the SD OS image, its SHA-256 files and `packages.txt`; no eMMC images. Update the About text and topics of the repository (`gh repo edit`) |
